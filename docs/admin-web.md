# 管理者向けWeb画面設計

このドキュメントは、管理者APIを利用するWeb画面の構成、操作フロー、安全対策をまとめる。記載した管理者向けWeb画面は実装済みである。

## 対象範囲

- 利用者一覧・検索・絞り込み
- 一般利用者の登録
- 利用者詳細と基本情報の更新
- 有効化・無効化・ロック解除
- 全セッション失効
- 一時パスワード再発行
- 顔認証用画像の登録・更新
- 管理操作監査ログの確認

管理者による他人の入退室履歴閲覧、利用者の物理削除、管理者権限の変更は対象外とする。管理者アカウントの作成・昇格・降格はCLIだけで行う。

## 画面構成

### 共通ナビゲーション

管理者でログインしている場合だけ、ヘッダーから次の画面へ移動できるようにする。

- 自分の履歴
- 利用者管理
- 監査ログ

一般利用者には管理者向けナビゲーションを表示しない。一般利用者が管理者画面のURLへ直接アクセスした場合は本人向け画面へ戻す。ただし、フロントエンドの表示制御は補助的なものとし、正式な認可は管理者APIで行う。

### 利用者一覧

Pathは `/admin/users` とする。

表示項目は次のとおり。

- 氏名
- 学籍番号
- メールアドレス
- 役割
- 顔画像の登録状態・登録枚数
- 有効・無効
- ロック状態
- 更新日時

利用者は数十人程度であるため、`GET /api/v1/admin/users` から全件を取得する。ページングは設けず、次の検索と絞り込みをフロントエンドで行う。

- 氏名・学籍番号・メールアドレスの部分一致検索
- 有効・無効
- ロック中
- 管理者権限の有無

各行の「詳細」から利用者情報編集モーダルを、「顔登録」から顔認証用画像モーダルを、「アカウント」からアカウント操作モーダルを開く。

### 利用者情報編集

Pathは `/admin/users/:userId` とし、利用者一覧の上にモーダルとして表示する。基本情報を1列で配置する。

- 氏名、LCD表示名、メールアドレスを編集できる
- 学籍番号、利用者種別、管理者権限は読み取り専用で表示する
- 入退室履歴は表示しない

状態変更は画面だけを先に更新せず、APIの成功レスポンスを受け取ってから反映する。

### アカウント操作

利用者一覧からモーダルとして表示する。有効化、無効化、ロック解除、全セッション失効、一時パスワード再発行を実行できる。

### 利用者登録

Pathは `/admin/users/new` とする。利用者種別、生徒の場合は学籍番号、氏名、LCD表示名、メールアドレスを入力し、作成される利用者は `isAdmin: false` とする。先生は学籍番号とLCD表示名を任意とし、未入力の場合はNULLを保存する。顔認証用画像はこの画面では登録せず、学籍番号を持つ作成済み利用者の詳細から登録する。

登録成功後は次の情報を表示する。

- 作成した利用者
- 一時パスワード
- 紐付けた未照合イベント件数

通信結果を確認できなかった場合は利用者を再作成せず、一覧で作成結果を確認してから一時パスワードを再発行する。

利用者一覧には顔画像の状態を「未登録」または登録枚数で表示する。一覧から開く顔認証用画像モーダルでは現在の状態を確認し、画像を1〜10枚選択して登録内容を全置換する。画像は `image/*`、1枚あたり10MB以下に制限する。

ブラウザは編集画面で選択した画像をReact stateと送信中のrequestだけで扱い、URL、Local Storage、Session Storageへ保存しない。管理APIを経由して送信し、PythonアプリのURLとBearerトークンはブラウザへ公開しない。

### 監査ログ

Pathは `/admin/audit-logs` とする。

- 操作日時
- 操作した管理者
- 対象利用者
- 操作内容
- 変更フィールド

初回は既定の50件を取得し、`nextCursor` がある場合だけ「さらに読み込む」ボタンを表示する。自動無限スクロールは使用しない。

監査ログが返す利用者IDは、取得済みの利用者一覧を使って現在の氏名と対応付ける。氏名は補助表示とし、監査上の正式な識別子は利用者IDとする。利用者は物理削除しないため、対象利用者は一覧から解決できる。

## 一時パスワードの表示

利用者登録とパスワード再発行の成功時に、APIから返された一時パスワードを一度だけ表示する。

- コピーボタンを用意する
- 閉じる前に管理者が保存済みであることを確認できる操作を設ける
- 表示中のReactコンポーネントの状態だけで保持する
- URL、アプリケーションログ、Local Storage、Session Storageへ保存しない
- 画面を閉じた後は再表示しない
- 紛失した場合は再度パスワードをリセットする
- APIレスポンスを受け取った画面ではキャッシュを前提にしない

## 確認が必要な操作

次の操作には、対象者の氏名と学籍番号を含む確認ダイアログを表示する。

- 利用者の無効化
- 全セッション失効
- 一時パスワード再発行

基本情報の保存、有効化、ロック解除には確認ダイアログを表示しない。成功または失敗を操作箇所の近くへ表示する。

管理者自身の無効化ボタンは画面上で無効にし、API側の禁止処理も維持する。管理者自身の全セッション失効は許可し、成功レスポンスを受け取った直後にログイン画面へ移動する。

## エラー表示

管理者APIのエラーを次のように表示する。

| Error code | 表示方針 |
| --- | --- |
| `USER_EMAIL_ALREADY_EXISTS` | メールアドレス入力欄へ重複エラーを表示する |
| `USER_STUDENT_NUMBER_ALREADY_EXISTS` | 学籍番号入力欄へ重複エラーを表示する |
| `CANNOT_DISABLE_SELF` | 自分自身は無効化できないことを操作箇所へ表示する |
| `LAST_ADMIN_REQUIRED` | 最後の有効な管理者を無効化できないことを表示する |
| `USER_NOT_FOUND` | 一覧へ戻り、対象が存在しないことを表示する |
| `AUTHENTICATION_REQUIRED` | ログイン画面へ移動する |
| `ADMIN_PERMISSION_REQUIRED` | 本人向け画面へ移動する |
| `FACE_AUTH_APP_UNAVAILABLE` | Python顔認証アプリへ接続できないため再試行を案内する |
| `FACE_AUTH_APP_REJECTED` | 画像の確認と再選択を案内する |

通信失敗時は入力内容を維持し、再試行できるようにする。

## フロントエンド構成案

管理者機能は `apps/web/src/features/admin/` 配下にまとめ、利用者向け履歴画面と分離する。

```text
features/admin/
├─ AdminLayout.tsx
├─ users/
│  ├─ UserListPage.tsx
│  ├─ UserDetailPage.tsx
│  ├─ CreateUserPage.tsx
│  └─ TemporaryPasswordDialog.tsx
└─ audit/
   └─ AuditLogPage.tsx
```

管理者APIクライアントと管理者用の型も、既存の共通API処理を再利用しながら管理者機能として分離する。

## HTTPS

管理画面はセッションCookieと一時パスワードを扱うため、実運用開始前にHTTPSを導入し、`SESSION_COOKIE_SECURE=true` を設定する。証明書、リバースプロキシ、LAN内端末への信頼方法はPhase 7で確定する。
