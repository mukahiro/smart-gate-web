# Web利用者認証設計

このドキュメントは、Webアプリを利用する研究室メンバーの認証と、入退室イベントを利用者へ紐付ける方法をまとめる。

データモデル、学籍番号によるイベント紐付け、保守者向けCLI、Web認証API、ログイン処理、セッション処理、利用者向けWeb画面は実装済みである。

## 対象範囲

- メールアドレスとパスワードによるWebログイン
- SQLiteで管理するCookieベースのセッション
- ログイン、ログアウト、ログイン中利用者取得API
- 保守者による利用者登録とパスワード再設定
- 認証アプリが取得した学籍番号と内部利用者の紐付け
- ログイン、本人の履歴確認、パスワード変更を行うWeb画面

顔認証・カード認証そのものと、カードID・顔認証用IDから学籍番号を取得する処理はPython認証アプリ側の責務とする。このリポジトリではカードID、顔特徴量、顔画像を永続保存しない。管理者による顔画像登録時に限り、画像をPython認証アプリへHTTP転送する間だけメモリ上で扱う。

## 識別子

### 内部利用者ID

`users.id` にはUUIDなどの、システム内部で不変なIDを使用する。学籍番号を主キーやセッションIDとして使用しない。

### 学籍番号

学籍番号の表示形式は `xx-xxxx-xxx-x` で、`x` は数字である。APIとDBではハイフンを除いたASCII数字10桁を正規形とする。

```text
表示形式: 12-3456-789-0
正規形:   1234567890
```

- JSON、TypeScript、SQLiteのすべてで文字列として扱う
- validationは `^[0-9]{10}$` とする
- 先頭のゼロを保持する
- DBには正規形だけを保存する
- 画面表示時のみ必要に応じてハイフンを付ける
- 学籍番号は再利用しないことを原則とする

保守者向けの登録処理では、ハイフンあり・なしの両形式を受け付け、正規形へ変換してよい。

## データモデル

日時カラムはoffset付きISO 8601文字列としてSQLiteへ保存する。

### `users`

| Column | Description |
| --- | --- |
| `id` | 内部利用者ID、主キー |
| `student_number` | 正規形の学籍番号、UNIQUE |
| `name` | 通常表示名 |
| `lcd_display_name` | LCD表示名 |
| `email` | 表示用メールアドレス |
| `email_normalized` | 前後空白除去・小文字化した検索用メールアドレス、UNIQUE |
| `role` | `member` または `admin`。既定値は `member` |
| `is_active` | 利用者の有効状態 |
| `created_at` | 作成日時 |
| `updated_at` | 更新日時 |

### `user_credentials`

通常の利用者情報から認証情報を分離する。

| Column | Description |
| --- | --- |
| `user_id` | `users.id` への外部キー、主キー |
| `password_hash` | Argon2idのパスワードハッシュ |
| `failed_login_count` | 連続ログイン失敗回数 |
| `locked_until` | ロック期限、未ロック時はNULL |
| `password_changed_at` | パスワード変更日時 |
| `updated_at` | 更新日時 |

### `sessions`

| Column | Description |
| --- | --- |
| `token_hash` | 生トークンをSHA-256でハッシュ化した値、主キー |
| `user_id` | `users.id` への外部キー |
| `created_at` | ログイン日時 |
| `last_seen_at` | 最終利用日時 |
| `idle_expires_at` | 無操作期限 |
| `absolute_expires_at` | 絶対期限 |

生のセッショントークンはDBに保存しない。

### `attendance_events` の利用者紐付け

入退室イベントには次の両方を保存する。

| Column | Description |
| --- | --- |
| `student_number_snapshot` | 認証アプリから受信した正規形の学籍番号 |
| `user_id` | `users.id` への外部キー。未照合時はNULL |

未登録の学籍番号でもイベントは必ず保存する。利用者登録後、同じ学籍番号を持つ `user_id IS NULL` のイベントを利用者へ紐付ける。利用者登録と未照合イベントの更新は同じトランザクションで行う。

これにより、認証成功イベントを失わず、利用者登録後に過去の履歴を復元できる。学籍番号が後から変更されても、紐付け済みの履歴は内部利用者IDで同じ利用者に紐付き続ける。

## パスワード

- Argon2idでハッシュ化する
- 平文パスワードをDBやログへ保存しない
- パスワード作成・再設定時は12文字以上、128文字以下とする
- ログイン入力時は1文字以上、128文字以下として認証失敗と入力制約を分離する
- 現在はmemory cost 19 MiB、iteration 2、parallelism 1とし、Raspberry Pi実機で再調整する
- パスワード再設定時は失敗回数とロックを解除し、利用者の全セッションを失効させる

## ログイン失敗制限

- 5回連続で失敗したら15分間ロックする
- ロック期限経過後の次回試行では失敗回数をリセットする
- ログイン成功時は失敗回数とロック状態をリセットする
- 未登録メールでもダミーのArgon2idハッシュを検証する
- メール未登録、パスワード不一致、利用者無効、ロック中は同じエラーを返す

## セッション

- 暗号学的に安全な32バイトのランダムトークンを生成する
- Cookieには生トークン、SQLiteにはSHA-256ハッシュだけを保存する
- 複数端末からの同時ログインを許可する
- 無操作期限は2時間とする
- ログインからの絶対期限は12時間とする
- `last_seen_at` と無操作期限の更新は、SQLiteへの書き込みを抑えるため最大5分に1回とする
- 通常のログアウトでは現在のセッションだけを失効させる
- パスワード再設定または利用者無効化時は、その利用者の全セッションを失効させる
- 期限切れセッションはアクセス時、API起動時、新規ログイン時に削除する

### Cookie

| Attribute | Value |
| --- | --- |
| Name | `smart_gate_session` |
| `HttpOnly` | `true` |
| `SameSite` | `Lax` |
| `Path` | `/api/v1` |
| `Max-Age` | `43200`（12時間） |
| `Secure` | 環境設定で切り替える |

HTTPSの導入判断は保留中である。`Secure=false` の場合は起動時に警告し、HTTP運用ではLAN内でもパスワードとセッションを盗聴される危険があることを運用資料へ明記する。本番環境での必須化はデプロイ設計時に決める。

## Web認証API

詳細なHTTP仕様は `docs/endpoints.md` を参照する。

- `POST /api/v1/auth/login`
- `POST /api/v1/auth/logout`
- `GET /api/v1/auth/me`
- `POST /api/v1/auth/change-password`

本人が任意でパスワードを変更する `POST /api/v1/auth/change-password` を実装済みである。一時パスワードからの変更も強制せず、通常のパスワード変更として扱う。変更成功時は現在を含む全セッションを失効させ、再ログインを求める。

認証必須APIはCookieからセッションを検証し、Hono Contextへ内部利用者IDを格納する。本人の履歴を取得するAPIは、リクエストから任意の利用者IDや学籍番号を受け取らず、Context上の内部利用者IDだけを使用する。

WebとAPIは同一オリジンで運用し、Cookie認証を使うAPIではOriginを検証する。任意オリジンへのcredential付きCORSは許可しない。Python認証アプリ向けのBearer認証とはmiddlewareを分離する。

## 利用者の保守

一般利用者向けのサインアップとパスワードリセット画面は作成しない。現行の保守者向けCLIに加えて、管理者向けの利用者管理APIをPhase 5で実装した。

- 管理者アカウントの作成・昇格・降格はCLIだけで行う
- 管理者APIで作成する利用者は一般利用者とする
- 利用者作成、基本情報更新、有効・無効切り替え、ロック解除を管理者APIで行う
- パスワード再設定では英大文字・数字12文字の一時パスワードを一度だけ返し、全セッションを失効させる
- `mustChangePassword`は導入せず、一時パスワードの変更は強制しない
- 管理操作は監査ログへ保存する
- 管理者でも他人の入退室履歴は閲覧できない

詳細は `docs/admin-api.md` を参照する。現在のCLIではパスワードをコマンドライン引数へ渡さず、対話入力で受け取る。
