# 要件定義

## 1. システム概要

本システムは、研究室メンバーが入室または退出を選択し、顔認証またはカード認証によって本人確認を行うことで、入退室履歴を記録するシステムである。

記録された履歴は、利用者本人がWebアプリ上で確認できる。システムはRaspberry Pi上で動作し、ローカルネットワーク内で利用する。

## 2. 目的

- 研究室への入室・退出時刻を記録する
- 利用者本人が自身の過去の入退室履歴を確認できるようにする
- 顔認証・カード認証結果をWeb API経由で保存する
- 認証結果をLCDへ表示し、利用者へ記録結果を通知する

本システムは、管理者による勤怠管理や監視を主目的としない。

## 3. 利用者

### 研究室メンバー

- 入室または退出操作を行う
- 顔認証またはカード認証を利用する
- Webアプリへログインする
- 自身の入退室履歴を確認する

### システム保守者

- 利用者情報や認証情報を登録する
- システムの設定および保守を行う

## 4. システム構成

```text
Raspberry Pi
├─ Python認証アプリ
│  ├─ 入室・退出ボタン
│  ├─ カメラ
│  ├─ カードリーダー
│  └─ 20文字×4行LCD
├─ Hono API
├─ React Webアプリ
└─ SQLite
```

Python認証アプリ、Hono API、React Webアプリ、SQLiteは同一のRaspberry Pi上で動作する。

## 5. 入退室記録要件

### 5.1 操作方式

利用者は認証前に「入室」または「退出」ボタンを押す。押されたボタンによって記録するイベント種別を決定する。

### 5.2 認証方式

- 顔認証
- カード認証

### 5.3 顔認証

- 顔認証は常時実行しない
- 入室または退出ボタン押下時に認証を開始する
- ボタン押下後にカメラで静止画を撮影する
- 撮影した画像を使用して顔認証を行う
- 必要に応じて短時間に複数枚撮影する
- 顔認証に使用した画像は原則として保存しない

### 5.4 カード認証

- 入室または退出ボタン押下後にカード読み取りを受け付ける
- 登録済みカードから利用者を特定する

### 5.5 認証待機

- ボタン押下後、一定時間のみ認証を受け付ける
- 認証成功後は待機状態を解除する
- 一定時間認証されなかった場合は自動的にキャンセルする
- 認証待機中であることをLCD等で通知する

### 5.6 API送信

認証成功後、Python認証アプリはHono APIへ以下を送信する。

- イベントID
- 学籍番号（ハイフンなしの数字10桁）
- 入室または退出
- 顔認証またはカード認証
- 認証日時
- 顔認証の場合は信頼度
- 認証端末情報

カードID・顔認証用IDから学籍番号を取得する処理はPython認証アプリ側で行う。Hono APIはカードID、顔認証用ID、顔特徴量を受け取らない。

学籍番号に対応する利用者がHono API側に未登録でも、認証イベントは失わずに保存する。未登録イベントは学籍番号を保持した未照合状態とし、利用者登録後に同じ学籍番号で紐付ける。

### 5.7 重複防止

- 各認証イベントには一意なイベントIDを付与する
- 同一イベントの再送による二重登録を防止する
- 同一人物による短時間の同一操作は重複として扱えるようにする

### 5.8 通信失敗

- API送信に失敗した場合、認証イベントをローカルへ一時保存する
- API復旧後に未送信イベントを自動再送する
- 再送時もイベントIDによって二重登録を防止する

## 6. LCD表示要件

### 6.1 LCD仕様

- 20文字×4行
- 使用可能文字は半角英数字、半角カタカナ、対応記号のみ

### 6.2 表示内容

- 認証待機状態
- 認証成功
- 認証失敗
- 入室記録成功
- 退出記録成功
- API通信失敗
- 利用者のLCD表示名
- 記録時刻

### 6.3 LCD表示名

通常の氏名とは別にLCD表示専用の名前を登録する。

```text
通常氏名：山田 太郎
LCD表示名：ﾔﾏﾀﾞ ﾀﾛｳ
```

LCD表示名の制約：

- 最大20文字
- 半角英数字
- 半角カタカナ
- 半角スペース
- LCDが対応する一部記号

### 6.4 APIレスポンス

APIは入退室記録後、以下を返す。

- 処理結果
- 記録種別
- 記録時刻
- LCD表示名
- 結果コード

Python認証アプリはAPIレスポンスをもとにLCD表示を生成する。

## 7. Webアプリ認証要件

### 7.1 ログイン

- メールアドレスとパスワードでログインする
- 未ログイン状態ではログイン画面以外を利用できない
- 認証状態はCookieベースのセッションで管理する
- ログアウト機能を提供する
- セッション期限切れ時はログイン画面へ遷移する
- 無操作状態が2時間続いたらセッションを失効させる
- ログインから12時間経過したら、操作中でもセッションを失効させる
- 複数端末からの同時ログインを許可する

### 7.2 パスワード

- パスワードを平文で保存しない
- Argon2idでハッシュ化する
- パスワード作成・再設定時は12文字以上、128文字以下とする
- 5回連続でログインに失敗したら15分間ロックする
- エラー表示からメールアドレスの登録有無を判別できないようにする
- パスワード再設定時は利用者の全セッションを失効させる
- 利用者本人がログイン後にパスワードを変更できる
- 本人によるパスワード変更時は、現在を含む全セッションを失効させる
- 管理者による再設定では一時パスワードを発行するが、変更は強制しない
- 一時パスワードは紛らわしい文字を除く英大文字・数字12文字とする
- 一時パスワードの変更状態を管理するカラムは追加しない

### 7.3 アカウント管理

- 一般利用者向けのサインアップ機能は提供しない
- 管理者APIで利用者登録、基本情報更新、パスワード再設定、有効・無効切り替え、ロック解除を行えるようにする
- 利用者一覧は全件を返し、検索と絞り込みはフロントエンドで行う
- 利用者作成時に一時パスワードを生成し、レスポンスで一度だけ返す
- 管理者が利用者作成時に生徒または先生を選択する
- 生徒は学籍番号とLCD表示名を必須、先生は任意とする
- 有効化、無効化、ロック解除、全セッション失効は冪等にする
- 管理者アカウントの作成・昇格・降格は保守者向けCLIでのみ行う
- パスワードはCLIのコマンドライン引数に含めず、対話入力する
- 利用者の物理削除は提供しない

### 7.4 管理者権限

- 利用者種別とシステム管理者権限を分離する
- 利用者種別は生徒または先生とする
- 生徒と先生のどちらにもシステム管理者権限を付与できる
- 管理者APIはCookieセッションと管理者権限で保護する
- 管理者は利用者を管理できるが、他人の入退室履歴は閲覧できない
- 管理者APIからシステム管理者権限を変更できない
- 管理操作は監査ログへ保存する
- 監査ログは削除期限を設けず無期限に保管する
- 監査ログ一覧は操作日時と監査ログIDの複合cursorで取得する
- cursorは `occurredAt` と `id` のJSONをBase64URLへ変換し、復号後に厳密に検証する

## 8. 履歴確認要件

### 8.1 閲覧範囲

- 利用者は自身の入退室履歴のみ閲覧できる
- 他の利用者の履歴は閲覧できない
- フロントエンドから任意の利用者IDを指定して履歴を取得できないようにする
- APIはログイン中のセッションに紐づいた利用者の履歴のみ返す

### 8.2 カレンダー表示

- 月単位のカレンダー形式で表示する
- 初期表示は当月とする
- 前月・翌月へ移動できる
- 入退室記録が存在する日をカレンダー上で識別できる
- 本日を識別できる

### 8.3 日別詳細

カレンダーの日付を選択すると、以下を確認できる。

- 入室または退出
- 記録日時
- 認証方法
- その日の履歴一覧
- 入室または退出記録の不足

### 8.4 滞在時間

入室と退出の対応が取れる場合は、参考情報として滞在時間を表示できる。

ただし、ボタンの押し間違い、認証忘れ、通信障害、重複操作などがあり得るため、正確性は保証しない。不完全な履歴をシステムが自動補完しない。

## 9. プライバシー要件

- 利用者は他人の入退室履歴を閲覧できない
- APIでも本人以外の履歴を返さない
- 顔認証用画像を履歴画面へ表示しない
- 顔画像は原則として保存しない
- 顔特徴量やカード情報へのアクセスを制限する
- 通常の利用者情報と認証用データを適切に分離する

## 10. データ要件

### 利用者

- 内部利用者ID
- 学籍番号（生徒は必須、先生は任意。ハイフンなしの数字10桁、文字列、重複不可）
- 氏名
- LCD表示名
- メールアドレス
- 有効状態
- 利用者種別（生徒または先生）
- システム管理者権限の有無

### Web認証情報

- 内部利用者ID
- Argon2idパスワードハッシュ
- 連続ログイン失敗回数
- ロック期限
- パスワード変更日時

カードID・顔認証用IDと学籍番号の対応はPython認証アプリ側で管理する。

### 入退室イベント

- イベントID
- 認証時の学籍番号
- 内部利用者ID（未照合時は未設定）
- 入室または退出
- 認証方法
- 認証日時
- API受信日時
- 顔認証信頼度
- 認証端末
- 送信状態

### セッション

- セッショントークンのハッシュ
- 内部利用者ID
- 作成日時
- 最終利用日時
- 無操作期限
- 絶対期限

### 管理操作監査ログ

- 監査ログID
- 操作した管理者の内部利用者ID
- 操作種別
- 対象利用者の内部利用者ID
- 操作日時
- 変更した項目名

パスワード、パスワードハッシュ、セッショントークン、変更前後の機密値は監査ログへ保存しない。

## 11. 非機能要件

- Raspberry Pi上で動作する
- ローカルネットワーク内で利用できる
- インターネット接続がなくても基本機能が動作する
- OS起動時に各アプリケーションを自動起動する
- 異常終了時に自動再起動する
- 認証イベントの消失を防止する
- SQLiteの定期バックアップを取得する
- Raspberry Piの時刻をNTPで同期する
- 日本時間で日時を表示する
- 長期運用ではUSB SSDの使用を推奨する

## 12. 対象外

初期実装では以下を対象外とする。

- 管理者による全利用者の履歴閲覧
- 勤怠管理
- 出席・欠席判定
- 遅刻判定
- 研究時間の正確な算出
- クラウド公開
- スマートフォンネイティブアプリ
- 顔認証アルゴリズム自体の新規開発
- 利用者による入退室履歴の自由な追加・変更
